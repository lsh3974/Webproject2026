# 동네 장터 UI — 구매자·판매자·주문 예약

> 이 문서는 8번 기반 최초 디자인 작업 기록이다. 11번 QR 수령까지의 현재 기준과 검증은 [UI-PICKUP.md](UI-PICKUP.md)를 따른다. 아래의 과거 main 삭제 오류는 현재 main 상태를 의미하지 않는다.

## 기준과 범위

- 기준: `main`의 `11798ea` (8번 주문·수량 예약 병합), 작업 브랜치: `codex/market-ui`.
- 선택한 1번 시안: 포레스트 그린 `#285442`, 크림 배경, 흰 카드, 둥근 모서리.
- 구매자: 홈, 공동구매 목록·상세, 로그인·회원가입, 접근 제한 화면.
- 판매자: 매장/상품/공동구매의 목록·등록·수정, 총 9개 화면.
- 예약: 대상 상품 선택, 수량 입력, 내 주문 목록, 주문 상세, 총 4개 화면.
- 총 19개 기본 화면. 취소·만료·결제 완료·환불·빈 주문·예약 불가·빈 검색 결과 7개 상태도 검토한다.
- 결제 완료·환불은 기존 상태의 표시만 검증했다. 9번 결제 API 구현이나 결제 버튼 활성화는 포함하지 않는다.

## 화면 연결

1. `/` → `/group-purchases` → `/group-purchases/{id}`.
2. 상품 상세의 **수량 예약하기** → `/orders/new?groupPurchaseId={id}`.
3. 기존 `POST /orders/new` → `/orders/{id}` → `/orders`.
4. 로그인한 사용자는 상단 **내 주문·예약**에서 이력을 확인한다.
5. 판매자는 **판매자 센터** → 내 매장 → 상품 관리/공동구매 관리로 이동한다.

목록·상세는 기존처럼 비회원도 공개 대상만 조회한다. 예약은 로그인 필요, 판매자는 자기 매장 예약 불가다.
기존 역할별 로그인 성공 이동을 사용하므로 비회원의 예약 진입 후 로그인 시 돌아갈 경로는 기존 로그인 정책을 따른다.

## 팀원이 이어서 수정할 파일

| 파일 | 역할 |
|---|---|
| `templates/fragments/ui.html` | 공통 CSS/JS, 구매자·판매자 헤더, 푸터 |
| `static/css/market.css` | 색상, 간격, 카드, 폼, 반응형 스타일 |
| `static/js/ui.js` | 현재 메뉴 표시, 상품 이미지 실패 시 대체 안내 |
| `templates/group-purchases/` | 구매자 목록·상세와 예약 진입 |
| `templates/order/` | 8번 기존 폼·상태를 사용하는 예약 화면 |
| `templates/seller/` | 기존 필드와 처리 주소를 유지한 판매자 화면 |

새 화면은 `fragments/ui :: assets`, 적절한 헤더, `ui-app` body, `main id="main"`, 공통 푸터를 사용한다.
Bootstrap 5.3.8 CSS/JS는 `static/*/vendor/`에서 로컬 제공한다. 외부 CDN이 막혀도 레이아웃이 유지된다.
이미지 배너는 팀이 제공한 초기 HTML의 이미지를 재사용했다. `images/ui/sample-*.svg`는 테스트·미리보기 데이터용이다.
실제 상품 화면에는 기존 DB의 이미지 URL이 전달되며 샘플 상품을 실제 DB에 추가하지 않는다.

이번 변경은 템플릿·정적 리소스·검증·문서에 한정한다. 운영 Java, SecurityConfig, DB 연결, SQL, pom.xml은 변경하지 않는다.
수량·예약 시간·권한·결제 정책은 기존 서비스가 결정한다. 판매 단위가 `1팩`인 경우 수량과 붙여 `461팩`으로 보이지 않도록 표시를 분리한다.
상품 이미지 수정 입력은 `/uploads/...` 같은 기존 상대 주소도 유지할 수 있고, 가격 입력은 1원 단위의 유효한 기존 값을 허용한다.

## 검증 방법과 한계

Java 17 환경에서:

```powershell
.\mvnw.cmd test
```

- 전체 59개 테스트 통과: 기존 52개 + `MarketUiIntegrationTest` 7개.
- 실제 Thymeleaf 렌더링, 폼 바인딩·오류 메시지, CSRF와 판매자 권한, 비회원 목록·상세 공개, 예약 생성·취소를 검증한다.
- 판매자 매장/상품/공동구매 등록·수정, 게시, 판매 상태 변경을 확인한다.
- Chrome에서 26개 화면 × 390/768/1440px = 78개 렌더링을 확인했다. 문서 가로 넘침, 누락 이미지, JS 실행 오류 없음.
- 수량 증감·최대/최소·금액 계산, 예약 불가의 비활성화, 상태별 취소 버튼, 타이머, 이미지 대체, 날짜 단축 입력, 현재 메뉴 표시도 확인한다.
- 긴 이름에 대해서는 360/1024px 추가 확인. 모든 데이터·모든 브라우저 조합의 보장을 뜻하지 않는다.
- H2 테스트 및 샘플 렌더링이다. 실제 MySQL, 실제 로그인 자격 증명, 이미지 파일 업로드의 디스크 저장, Toss 결제는 별도 로컬 확인 대상이다.

테스트 데이터로 화면을 내보내려면:

```powershell
.\mvnw.cmd "-Dtest=MarketUiIntegrationTest" "-Dmarket.previewDir=target/market-preview" test
```

`target/market-preview`는 서버에서 렌더링된 검증 원본이다. 배포 ZIP의 `preview/index.html`은 CSS/JS 경로까지 변환한 오프라인 미리보기다.
미리보기 상단의 노란 화면 선택 메뉴는 실제 앱에 들어가지 않는다. 저장·로그인·취소는 전송하지 않고, 샘플 대기 타이머만 열 때 14분으로 재시작한다.

## 별도 발견: main의 공동구매 삭제 조회 오류

디자인 전환 후 판매자 삭제까지 확장 검증하는 과정에서 다음 기존 서버 오류를 재현했다.

- 재현: 주문·예약이 없고 `currentQuantity = 0`인 공동구매를 판매자가 삭제한다.
- 위치: `GroupPurchaseService.deleteGroupPurchase` → `OrderRepository.existsByGroupPurchaseId`.
- 오류: 생성된 JPQL이 `o.groupPurchaseId`를 참조하지만 `Order`는 `groupPurchase` 연관 필드를 가진다. `UnknownPathException` 발생.
- 같은 메서드를 사용하는 초안 복귀 조건에도 영향이 있을 수 있다. 초안 복귀는 별도로 재현하지 않았다.
- 8번 담당 검토 방향: 존재 확인 쿼리에서 `o.groupPurchase.id`를 명시하고, 주문 유무별 삭제 및 초안 복귀 통합 테스트를 추가한다.
- 운영 Java는 기준 main과 동일하게 유지했다. 이 오류를 디자인 변경에 섞어서 고치지 않았다.
- 초기 확장 테스트는 이 삭제에서 실패했고, 최종 UI 폼 테스트는 등록·수정·게시·상태 변경까지만 검증한다. **59개 통과는 삭제 문제 해결을 의미하지 않는다.**
